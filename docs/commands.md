# Commands reference

Every `/autonovel:*` command, grouped by `context_mode`. Each row lists
the invocation hint, the model tier the adapter pins for the runtime,
and a one-line description.

The model tier maps to a concrete model per runtime — see
[`REWRITE-PLAN.md` §17](../REWRITE-PLAN.md#17-model-selection-per-command-frontmatter-model_tier).
Defaults on Claude Code are Opus 4.7 (heavy), Sonnet 4.6 (standard),
Haiku 4.5 (light); `project.yaml` can override per-series.

## Series-level commands

These read or write `shared/*` files and apply to the series as a whole.

| Command | Tier | Description |
|---|---|---|
| `/autonovel:add-character --name <name> [--role <role>] [--book <short-name>]` | standard | Add one character to the series cast; update `shared/characters.md`. |
| `/autonovel:add-source <url-or-doi> [--shortname <key>] [--weight primary|secondary] [--title "<title>"] [--research <topic>]` | standard | Add a URL or DOI to the bibliography and `shared/research/sources.yaml`; optionally re-run research. |
| `/autonovel:gen-canon [--book <short-name>] [--force]` | standard | Seed canon. Series-wide facts (world, characters, events, research — real history) → `shared/canon.md`; each book's outline-committed facts → `books/<book>/canon.md`. The shared half is not rewritten once populated (a second book must not regenerate the facts the first was drafted against). |
| `/autonovel:gen-characters` | heavy | Generate `shared/characters.md` from the world and the books' seeds. |
| `/autonovel:gen-world` | heavy | Generate `shared/world.md` from `project.yaml` and the books' seeds. |
| `/autonovel:promote-canon [--book <short-name>] [--dry-run] [--scope auto\|book\|series]` | standard | Promote pending canon entries from every book's `pending_canon.md` into canon. **Book-scoped:** chapter-derived facts → that book's `books/<book>/canon.md` (bind that book only); research-cited facts → `shared/canon.md`. De-dup / contradiction checks run against shared + the book's OWN canon, never a sibling book's. |
| `/autonovel:canon-partition --to-book <short-name> [--move-section <h>]... [--move-key <k>]... [--dry-run] [--no-llm]` | standard | One-time migration for a series created before book-scoped canon: moves every `(from <book> ch_NN)`-tagged bullet out of `shared/canon.md` into that book's `canon.md` mechanically, then LLM-classifies the untagged leftovers (verifiable history stays shared; the book's plot inventions move via `--move-key` / `--move-section`). Idempotent. Run before adding a sibling book or a rewrite. |
| `/autonovel:rename-character --old <old-name> --new <new-name> [--book <short-name>]` | standard | Globally rename a character with word-boundary safety (script-based, never LLM rename). |
| `/autonovel:research "<topic>" \| --from-seed [--book <name>] \| --query "<question>"` | heavy | Three modes. **Topic:** live web research, writes sourced notes to `shared/research/notes/<slug>.md`. **From-seed:** auto-derive 2–4 topics from `seed.txt` + `project.yaml :: period` and run topic mode for each. **Query:** read every existing `shared/research/notes/*.md` (no web search) and answer the question with `[shortname]` citations — cross-source synthesis without re-firing research. Pair with `autonovel mechanical research-index <series>` for the structural "what's even in there" view. |
| `/autonovel:run-pipeline --books <name[,name...]> [--phase <phase>] [--max-cycles <N>]` | light | Drive the full pipeline across one or more books. Advisory orchestrator — every mutation goes through a sibling `/autonovel:*` command. |

## Book-level commands

These read or write files under `books/{book}/`. The `--book <short-name>`
argument is required when more than one book exists in the series.

> **If you're confused about which command to run when** —
> specifically how `draft`, `draft-pass`, `revise`, `revision-pass`,
> `brief`, `review`, and `reader-panel` relate to each other —
> read [`operating-guide.md` §0](operating-guide.md#0-how-the-editing-commands-relate)
> before this reference. The roles (atomic / sweep / whole-book
> reviewer / mechanical helper) and the call graph (which command
> automatically invokes which) are explained there. This file is
> a per-command reference; the relationships are in the operating
> guide.

### Drafting

| Command | Tier | Description |
|---|---|---|
| `/autonovel:design --book <short-name> [--from-book <from_book>] [--notes "<the author's direction>"] [--force]` | heavy | **Design the book before it is outlined** into `books/{book}/design.md`, working back from the climax (`shared/craft/DESIGN.md`): the scene where the protagonist answers the book's question by his own act and cost; the question (posed on the page in the first quarter); the one action, span and proportion; the one rival who wants the same prize (dated plan, on stage every act, wins once before the climax); the skills and knowledge the climax spends, each planted inside a contest of its own, tested, then paid (`P1…`); two or more rehearsals of the climax, one failing; the cast as a web (want, fear, secret, contradiction, signature, entrance in action); six to ten sequences that hand their results on; clocks, stakes ladder, reader questions per act; places (orientation, use, sensory signature, arrival, only-here moments, the set piece where each is seen whole through the viewpoint's eyes); voice; the genre's obligatory scenes. Self-tests D1–D13, a cold second reader (D14), then `design-validate`. `--from-book` is the re-design loop: creates `{book}` as a new isolated book if needed, copies the old book's art, reads its editor's letters, reviews and summaries (never its chapters), and writes a keep-ledger and a fault-ledger; `--notes` is the author's direction, which wins. |
| `/autonovel:cast --book <short-name> [--character <name>] [--force]` | heavy | **The character dossiers** into `books/{book}/cast.md`, so the people on the page have depth (`shared/craft/CHARACTER.md`). For each principal: want, need, fear, wound, the contradiction (each quality with the act that shows it), what they put first when forced to choose, secret, private life, how they see a room, humour, self-deception, body and standing, relationships, the pressure choices by chapter, what each chapter shows of them that no earlier one has, a private monologue for the writer only, and a return tag; a short entry with a return tag for every minor and ensemble player; a relationship table (history, who owes whom, what is never said, how it changes); tests C1–C12; a cold check for who still reads as a type. Real people are built from the research notes (cited), invention marked. `--character` rebuilds one entry. Read by `draft` (step 3d), `revise`, `gen-outline`, `deepen-character` and `evaluate` (`character_depth`). **Does NOT modify chapters.** |
| `/autonovel:gen-outline --book <short-name> [--force] [--add-spine]` | heavy | Generate the outline from the design (when `design.md` exists — binding: same question, climax, opponent, acts and chapter count; each chapter lists `sequence`, `plants`, `tests`, `payoffs`; checked with `design-validate --outline`; reassigns copied plates to the new chapters), seed, world, and characters. Commits to the book's spine in three parseable sections — `## Spine` (the one question the book asks and answers, want, opposing force), `## Stakes ladder` (one row per act, strictly higher on the same bet) and `## Causal spine` (`- N because M: <event>`; `after` marks a known weak link) — that `draft` / `draft-pass` hold each chapter to and `structure-review` / `evaluate` read. `--add-spine` retrofits the three sections onto an existing outline without touching its chapter entries. |
| `/autonovel:voice-discovery --book <short-name> [--force \| --upgrade]` | heavy | Fill the book-specific fingerprint in Part 2 of `voice.md`, draft per-character voice fingerprints into Part 4 when the cast count is ≥3, and append the Part 3 (Custom rubric) placeholder if missing. `--upgrade` is the safe path for existing books — preserves Parts 1 and 2 verbatim while adding Parts 3 and 4. `--force` regenerates everything. |
| `/autonovel:draft <chapter-number> --book <short-name>` | standard | Draft one chapter as full prose. Keeps a reader's map: every term a reader today may not know explained in plain words at first use (from `design.md` `## Terms`), one new person at a time, a first page that says where, when and what is at stake, a plain picture of each major place in its own time, and the chapter's `dateline`. A redraft of a chapter you have already read ends with a `/autonovel:diff` page against your last read. |
| `/autonovel:draft-pass --chapters <range> [--book <name>] [--retry-below <score>] [--no-revise-low] [--no-anachronism] [--no-promote] [--skip-eval] [--deep]` | heavy | "Write the rest of the book." Per chapter: draft (with its cold first reader) → anachronism check → evaluate → if score < threshold (default 7.0), brief + revise + re-eval (keep best). At sweep end: promote-canon. A per-chapter **SPINE CHECK** against the outline's `## Causal spine` sends a chapter that doesn't follow from the one before to a `kind: structural` revise even above threshold. With `--deep`: also run structure-review + reader-panel + Opus review on the whole book and surface the flagged-chapter list. Sequential only. Same per-chapter quality as `/autonovel:draft` plus immediate-fix-on-low-score, end-of-sweep canon coherence, and (in deep mode) the whole-book passes. |
| `/autonovel:summarize-chapter <chapter> \| --stale \| --all [--book <short-name>] [--force]` | standard | Write or refresh the 150–250-word continuity summary and stamp it with the chapter's fingerprint (`autonovel _stamp-summary`); `--stale` does every chapter whose summary no longer matches (`autonovel mechanical summary-check`). Rarely needed: commands that read summaries refresh out-of-date ones first, and `_end` holds any command that changed a chapter until its summary matches (the summary gate). Use it after a hand edit. |
| `/autonovel:chapter-summary [--book <short-name>] [--format markdown\|json]` | light | Print a one-line-per-chapter overview — Date / POV / Score / Words / Cast / Plot — for the active book. Pure mechanical (no LLM), pulls already-structured fields from chapter frontmatter, summary.md, and the latest eval log. The right tool for "which chapters happen in <date range>?" or "where does <character> appear?" or "which chapter scored lowest?" — scan the relevant column. `--format json` for piping. |
| `/autonovel:motifs [--book <short-name>] [--format markdown\|json]` | light | Per-chapter motif density tracker. Reads `books/{book}/motifs.md` (one bullet per motif: `- slug: keyword1, keyword2`), counts word-boundary matches in each `ch_NN.md`, and emits a markdown table. Flags motifs that drop to zero in the back half of the book if they were established in the front half — catches "set up an image, never paid it off" without scoring it. Pure mechanical. |
| `/autonovel:talk --book <short-name> "<question or suggestion>" [--target <chapter>]` | heavy | Conversational query+suggest layer over the finished prose. Three modes the command picks from your prompt: **Q+A** (e.g. *"explain why Jakob opened the book of accounts"* — answers, cites chapter+line); **Suggest-and-stage** (e.g. *"add some details about the book of accounts being out of alignment"* — queues an edit in `books/{book}/briefs/conversation.md` for the next `/autonovel:revise <N>` to apply); **Mechanical+suggest** (e.g. *"how many cipher-diary entries are referred to later? Cut the orphans"* — runs `mechanical entity-track` first, then queues a structured cut-list). Each invocation appends one turn to `conversation.md`; revise marks queued turns `applied` after using them. |
| `/autonovel:impact-of [--book <short-name>] [--source promote-canon\|gen-canon\|voice-discovery\|add-character\|gen-characters\|gen-world\|add-source\|rename-character\|merge-chapters\|reorder\|remove-chapter\|research] [--with-llm] [--format markdown\|json]` | light | After a foundation mutation, list the chapters that reference the now-wrong fact and emit an action checklist of `/autonovel:revise --chapter N` calls. Five detection shapes: **canon-driven** (`promote-canon`, `gen-canon`) parses `## Superseded` blocks and greps tokens unique to each prior value; **mtime-driven** (`voice-discovery`, `add-character`, `gen-characters`, `gen-world`, `add-source`) lists chapters drafted before the relevant foundation file's last update; **rename-verify** (`rename-character`) reads the most recent rename from `.autonovel/command-log.jsonl` and word-boundary-greps every chapter for the OLD name (catches stragglers the rename's sed missed — possessives, hyphens, unicode look-alikes, HTML entities); **renumber-refs** (`merge-chapters`, `reorder`, `remove-chapter`) greps prose for chapter-number cross-references (`Chapter VII`, `chapter 7`, `ch. 12`) so a renumber doesn't leave silently-wrong navigational pointers; **research** reads notes newer than the last canon timestamp and (LLM by default) scans chapters for contradictions against the notes' candidate canon entries. With `--with-llm` on canon-driven sources, a Haiku-tier classifier labels each match HIGH/MEDIUM/LOW/FALSE_POSITIVE so the action checklist only includes HIGH+MEDIUM. Read-only by contract. |
| `/autonovel:genre [--book <name>] [--list] [--set <genre>] [--subgenres <a,b>] [--add <genre>]` | heavy | Show or set a book's genre and subgenres (a book can be two: a biographical novel with a political thriller's engine), each with what its reader comes for; `--add` researches and writes a sourced guide in the standard sections to `shared/genres/<genre>.md` for a genre without one. The guide (`shared/craft/genres/<genre>.md`) is read by design, outline, cast, draft, revise, brief, the cold first reader, evaluate (extra dimension, e.g. `history`), adversarial-edit/apply-cuts (`MISPLACED`: moved, never cut), reader-panel, review, developmental-edit, structure-review, research, gen-world and appendix. |
| `/autonovel:dashboard [--book <short-name>] [--dimensions] [--threshold <float>] [--floor <float>] [--format markdown\|json]` | light | Per-book at-a-glance dashboard. Re-renders the latest per-chapter eval logs and `<ts>_full.json` (score / tension / beats-hit / irreversible_change) and augments with mechanical dimensions (cast size, scene count, dialogue density, motif density). Each row shows the chapter's **lowest dimension** beside its score (⚠ under `defaults.dimension_floor`) and the cold first reader's serious items; **Needs attention first** ranks the ten lowest chapter-dimension scores in the book. `--dimensions` prints every dimension for every chapter in groups (story, people and place, writing, genre), with mean and lowest rows. Adds ASCII sparklines, per-book aggregates (mean / median / range / longest sub-threshold streak / lowest dimension in the book), and re-runs the tension-drop alarm. Pure mechanical, no LLM call. |
| `/autonovel:story-map [--book <short-name>] [--refresh-threads]` | standard | The **reading surface** for "how does the plot develop?" — one self-contained HTML page (`books/{book}/edit_logs/story_map.html` + `story_map.json`; offline, light/dark, phone-friendly) with four tabs: **Synopsis** (every chapter summary in reading order under the outline's act headers, plus a one-line-per-chapter skim), **Threads** (plot threads × chapters, cells marked plant / turn / payoff / touch with the one-line state per touch, and the score / tension / irreversible-change curves directly underneath on the same chapter axis), **Characters** (presence grid + each principal's chapters with the per-chapter state change), **Timeline & places** (story time to scale, gaps over a year labelled; places visited vs only named). Threads come from `books/{book}/threads.md` — a hand-editable ledger (`## Thread: <name>` / `- ch <N> plant\|turn\|payoff\|touch: <state>`, `## Character: <name>`, `## Places`) the LLM writes on first run or `--refresh-threads` from the outline + summaries (never the prose) — else an outline `## Threads` ledger, else the outline's `events:` ids. Shows data (which chapters touch a thread, the longest gap), never verdicts. |
| `/autonovel:summaries [--book <short-name>] [--where '<expr>'] [--format markdown\|json]` | light | Filter the per-chapter summary table by a small DSL — `pov == "Lucia"`, `score < 7.0 and word_count > 3000`, `cast contains Niccolò`, `story_time >= "1521-11"`, `chapter in 5..12`, etc. Distinct from `/autonovel:talk` (LLM-mediated semantic Q+A) and `/autonovel:chapter-summary` (whole-table dump): pure mechanical, free, scriptable, stable semantics. |
| `/autonovel:dialogue [--book <short-name>] [--summary-only] [--format markdown\|json]` | light | Pre-flight dialogue-mechanics scanner. Six detectors: adverb-heavy speech tags, said-bookisms, repeated-verb stutters, action-beat-tag clusters (3+ in 10 lines), softening qualifiers in short retorts (`"Maybe,"`), and unattributed-dialogue runs (≥3 untagged paragraphs). **Review list, not a gate** — LLM judge in `/autonovel:evaluate` scores; this surfaces candidates. |
| `/autonovel:period-register [--book <short-name>] [--summary-only] [--format markdown\|json]` | light | Roll the period-bans scanner across every chapter and emit a worst-offenders ranking + per-chapter hit table. Useful before a typeset / publish pass to confirm the book stays in period across the full run. |
| `/autonovel:syntax-drift [--book <short-name>] [--threshold <float>] [--format markdown\|json]` | light | Per-chapter Flesch-Kincaid grade vs the book's voice/seed baseline (or median fallback). Catches modern syntax in period-correct vocabulary. Pure math, no curated word-lists. Review list, not a quality gate — the LLM judge in `/autonovel:evaluate`'s `voice_adherence` dimension scores. |
| `/autonovel:pov-bleed [--book <short-name>] [--summary-only] [--format markdown\|json]` | light | Heuristic POV-bleed scan — flag lines where a non-POV character is named with an interiority verb (`thought`, `felt`, `knew`, `realised`, …) or possessive interiority (`Niccolò's mind raced`). Reads `shared/characters.md` for the cast. False positives are common — treat as a review list, not a gate. |
| `/autonovel:import-book --book <short-name> --from <path> [--split-on '<regex>'] [--start <N>] [--pov <name>] [--keep-mode] [--overwrite] [--reverse-engineer] [--dry-run]` | light | Import an externally-written manuscript into `books/{book}/chapters/`. Splits a directory of `*.md` files (one chapter per file) OR a single combined manuscript (split on `^# `, fallback `^## `, fallback whole file). Writes autonovel-shape frontmatter + flips `project.yaml :: books[].mode` to `edit-imported` so `/autonovel:draft` refuses to overwrite. With `--reverse-engineer`, scan the imported prose for candidate character names (capitalised single-word tokens above a frequency threshold; structural-English reject list) and write or append `shared/characters.md` with a "Candidate cast (auto-detected)" block. Pure mechanical, no LLM — voice / outline reverse-engineering route through follow-up LLM commands (`voice-discovery` / `summarize-chapter` / `gen-outline`). |
| `/autonovel:series-arc [--threshold <float>] [--format markdown\|json]` | light | Series-arc score across ≥2 books: per-book completion (summary / eval / above-threshold), cross-book cast (characters in ≥2 books), backwards story-time jumps (intentional flashbacks vs structure problems), unresolved threads (opened in one chapter, never closed in any later one), composite arc score 0–10. Books whose `story_time_range`s overlap (a rewrite, a parallel POV) are listed under `overlapping_books` and the clock reset at their boundary is not counted as a backwards jump. Pure mechanical. |
| `/autonovel:show-dont-tell [--book <short-name>] [--summary-only] [--format markdown\|json]` | light | Per-chapter pre-flight scanner for tell-candidate lines (emotion-state, interiority verbs, perception filters, narrator labels). Wider net than the existing slop scanner; surfaces line-level targets for revise. The LLM judge in `/autonovel:evaluate` does the show-vs-tell ratio scoring. |
| `/autonovel:vagueness [--book <short-name>] [--summary-only] [--format markdown\|json]` | light | Per-chapter pre-flight scanner for **vague/abstract prose** — filler nouns (*thing, something, a lot*), empty intensifiers (*very, really*), unearned evaluative adjectives (*good, beautiful, interesting*), hedges (*seemed to, somehow*). A review queue for making prose concrete, **not a gate** (the LLM `concreteness` lens in `/autonovel:evaluate` is the real judge). Same "say the actual thing" discipline as the teaser VO. |

### Evaluation and revision

| Command | Tier | Description |
|---|---|---|
| `/autonovel:evaluate --phase foundation --book <name>` | heavy | Score the foundation. Includes `design` (`design.md` exists, `design-validate --outline` is OK, the climax turns on the protagonist's own act and seen plants, one rival for the same prize, wins earned by knowledge not luck; capped at 4 without a design; structure is now 35% of the weighting, a third of it `design`), `causal_spine` (does the outline's `## Spine` / `## Stakes ladder` / `## Causal spine` commit to one story, or to a sequence of self-contained wagers? capped at 5 when the sections are absent) and `clocks_paid`: every deadline / ultimatum / dated promise a beat sets must have a later beat that pays it as a scene, not a line of summary (the "missing scene" a reader panel finds later, caught in the outline). |
| `/autonovel:evaluate --phase series` | heavy | Score arc *quality* across ≥2 books. Pairs with `/autonovel:series-arc` (structural scoreboard); this LLM judge scores `series_question`, `early_setup_late_payoff`, `cross_book_character_growth`, `world_evolution_consistency`, `tonal_continuity`. Output includes a `unresolved_thread_payoff_plan` array brief / revise can act on. Eval log lands at `.autonovel/eval_logs/<ts>_series.json`. |
| `/autonovel:evaluate --chapter <N> --book <name>` | heavy | Score one chapter against the standard rubric plus `irreversible_change` (Stability Trap antidote), `beat_coverage` (per-scene goal/conflict/disaster-or-decision/consequence; surfaces `weakest_scenes` by index), `show_dont_tell_ratio`, **`concreteness`** (the LLM lens over the `vagueness` scanner — classifies each vague candidate *vague* vs *earned*, names the concrete specific it should become), **`character_depth`** (does each person who matters want something of their own, show their contradiction in an act, carry their history with the others — or read as a trait and a habit; reads `cast.md` and the first reader's "Who felt real"), **`sense_of_place`** (could a newcomer picture each place in its own time, seen through someone's attention rather than a lecture; a major place's first appearance held to its set piece), and any criteria in `voice.md` Part 3 (Custom rubric). For chapter 1, also scores `hook_strength` over the first 250 words. |
| `/autonovel:evaluate --full --book <name>` | heavy | Score the whole book, **weighted toward structure so chapter prose cannot carry the aggregate**: fifteen dimensions in four groups — Structure 50% (`causal_chain` 15, `through_line` 10, `escalation` 10, `removability` 10, `climax_convergence` 5), Arc & payoff 20% (`arc_completion` 7, `irreversible_change_arc` 5, `foreshadowing_resolution` 4, `clocks_paid` 4), Reader pull 15% (`pacing_curve` 8, `overall_engagement` 7), Prose & consistency 15% (`voice_consistency`, `show_dont_tell_arc`, `theme_coherence` 4 each, `world_consistency` 3) — and `raw_novel_score = min(weighted_mean, structure_subscore + 1.0)`. Reads the structure dossier (full summaries, positions, story-time gaps) and, when fresh, `structure_review.json`'s tables. Also: `clocks_paid` (whole-book clock ledger: each chapter-ending deadline and where / how it is paid, `unpaid_or_summary_clocks` for the brief loop), `irreversible_change_arc` (walks every (N→N+1) chapter pair, surfaces `cuttable_chapters`), `book_beat_coverage_score`, and `weak_beat_coverage_chapters`. Emits the per-chapter pacing-curve table + tension-drop alarms. |
| `/autonovel:evaluate --compare <N>,<M> --book <name> [--vs-book <other>]` | heavy | Head-to-head chapter pair. With `--vs-book`, chapter M comes from the other book — the cross-book comparison for a rewrite against its original (each judged against its own `voice.md`; emits `winner_book`). |
| `/autonovel:adversarial-edit <chapter> --book <short-name>` | heavy | Find 10–20 cut/rewrite candidates in one chapter. |
| `/autonovel:apply-cuts <chapter> --book <short-name> [--types OVER-EXPLAIN REDUNDANT] [--dry-run]` | light | Deterministically remove quotes flagged by adversarial-edit. |
| `/autonovel:reader-panel --book <short-name>` | heavy | Four-persona reader-panel review of a book's complete arc. Fourteen questions per persona: ten about the reading plus four about the book as one story — `book_in_one_sentence` (what it is about and the question it answers), `felt_like_episodes`, `chapter_to_cut` (a whole chapter), `pulled_vs_informed` — rolled up into a `book_level` block (do the four name the same question? episode and cut votes per chapter). |
| `/autonovel:review --book <short-name>` | heavy | Deep dual-persona manuscript review — literary critic + professor of fiction. Writes `edit_logs/review.md` (the prose) and `edit_logs/review.json` (numbered professor items with severity / type / qualified flags and a `stop_revising` verdict). `brief --from review` (and `--from auto`) reads the JSON, so the editorial letter reaches the rewrite. **`stop_revising` is gated on the book-level structure review**: it needs a fresh, valid `structure_review.json` scoring ≥ 4 with no removable chapter (checked by `autonovel mechanical structure-validate`), otherwise it says "run /autonovel:structure-review first". Items about chapter order, causation, act stakes or a removable chapter are typed `structural` and never count as qualified hedges. |
| `/autonovel:structure-review --book <short-name>` | heavy | **Book-level structural review — is it one story building to a climax, or a string of episodes?** Reads the whole manuscript, the seed, the outline and every chapter summary (via `autonovel mechanical structure-dossier`) and writes `edit_logs/structure_review.json` + `.md`: the through-line (one question; does the ending answer it?), a causal-chain table (ch N → N+1: *because* / *after* / *unrelated*, each "because" argued with a plot fact), an escalation ladder per act, a removability verdict per chapter (no later chapter breaks if it's cut = an anecdote), the climax build (converge or finish?), named failure modes (`anecdote-chain`, `motif-spine`, `chronicle-spine`, `late-through-line`, `reset-ladder`, …), a 1–5 structure score separate from prose, and 3–7 structural brief candidates that `brief --from auto` turns into `kind: structural` briefs (cross-chapter moves carry the exact `merge-chapters` / `remove-chapter` / `reorder` / `split-chapter` command for you to run). Sycophancy guards: strong prose is not evidence of structure, no hedging a structural defect, other reviewers read only after scoring, and `structure-validate` rejects a score above the rubric caps its own tables imply. Gates `review`'s stop-revising verdict. |
| `/autonovel:developmental-edit --book <short-name> [--focus "<concern>"] [--stage]` | heavy | **A developmental editor's full read and letter.** One reader reads every chapter in order, cold — before the seed, outline, summaries, eval logs and reviews — and appends fixed notes per chapter to `edit_logs/editor_read_notes.md` (what happens, what the reader wants to know, what pulls forward, caused by / sets up, the opposition, what the protagonist wants and is wrong about, time and narration, craft notes) with a running diagnosis every few chapters. A measurement pass counts what the diagnosis rests on (`structure-dossier` for gaps and positions, `prolepsis` for narrator flash-forwards, verified by reading), and an intent pass reads the seed, outline, voice and `briefs/conversation.md` to find which rules or staged edits caused each problem. Writes `edit_logs/editor_letter.md` (1,800–3,500 words): what the book is, what must survive revision, the story's problems ranked by cost to the reader (answering `--focus` in the author's words), what caused them, recommendations in order of effect for cost with the command for each, what not to do, the order of work, a recommendations ledger, and — written only after the diagnosis — where it disagrees with `structure-review`, `review` and the panel. ### Movie / teaser

Build spec: [`prd-movie-teaser-mode.md`](prd-movie-teaser-mode.md). Creative guide: [`teaser-craft.md`](teaser-craft.md). Backend map + free-tier/key setup: [`teaser-render-providers.md`](teaser-render-providers.md). Full pipeline shipped: `treatment` → `teaser-brief` (distil the through-line + turn + killer lines) → `teaser` (orchestrator: `teaser-beats` → `shot-prompts`) → `teaser-critique` (scores the **interestingness rubric** → `quality.json`) → `teaser-revise` (apply the critique in place, lift the weak quality dimensions + de-boring pass; loop until **both render gates** are READY) → `teaser-refs` (develop + approve character references) → `teaser-render` (offline `stub` to validate free, then `grok` real clips + vision critique) → `teaser-assemble` (ffmpeg stitch + viewer-panel cut critique). The planning commands (treatment → shot-prompts, critique) are **free, no generation**; `teaser-render` validates the whole chain for $0 via the offline `stub` backend before spending a real one; `teaser-assemble` runs ffmpeg locally. **Two render gates (Phase 11):** the structural story gate AND the quality gate (overall ≥ 7, no dimension < 5) — a structurally-complete-but-boring teaser is refused. **Phase 13 — `mode: short` (default):** a 45–60s, ≤12-shot micro-story carried by a single first-person **voiceover spine** (the only thing that makes independently-generated AI clips cohere); `--mode trailer` keeps the older longer montage shape. AI video has no continuity *between* clips, so few longer shots + one narrator beat a 30-shot montage.

| `teaser-archive-script <file> [--archive-dir <d>]` | Timestamp-archive a teaser **script** (`beats.md` / `teaser.json` / a shot file) to `teaser/script-takes/<name>_<UTC>.<ext>` before a `--force` re-run overwrites it (Phase 6). No-op if the file is absent; the `refs/` originals are untouched, so a full pipeline re-run changes the scripts but reuses the approved portraits/plates. |
| `teaser-ffmpeg-cmd <cut_list.json> [--versioned] [--out <mp4>]` | Print the (shell-ready) ffmpeg command that stitches a cut-list into one mp4. The command body runs it via `bash`; Python never invokes ffmpeg. `--versioned` timestamps the output (`<title>_teaser_<UTC>.mp4`) + reports a `latest` pointer so a re-assemble never clobbers an earlier cut (Phase 5.8). |

`autonovel mechanical <subcmd> --help` shows full flags for any
of them. Many emit JSON via `--format json` for piping.

## Frontmatter contract

Every command file under `commands/*.md` carries YAML frontmatter the
adapters parse and the contract tests verify:

```yaml
---
name: autonovel:<stem>
description: <one-line description>
argument-hint: "<argument-hint string>"
model_tier: heavy | standard | light
allowed-tools:
  - file_read
  - file_write
  - bash
  - task
  - web_search
  - web_fetch
reads:
  - <path>
writes:
  - <path>
context_mode: series | book | none
---
```

Tier-2 contract tests verify every `reads:` entry is mentioned in the
body, every `writes:` entry is described in the body, and every path
placeholder (`{book}`, `{chapter}`) resolves from `argument-hint`.
